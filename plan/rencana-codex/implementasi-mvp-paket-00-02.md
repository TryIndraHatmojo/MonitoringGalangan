# Monitoring Galangan · Implementasi paket 00, 01, dan 02

## Ringkasan

Bangun fondasi MVP web yang memungkinkan Administrator mengelola organisasi, pengguna, dan proyek kapal, serta memungkinkan Planner menyusun WBS dan menerbitkan baseline melalui persetujuan proyek. Setelah paket 02, API baca proyek dan WBS dapat diuji dengan token perangkat. Urutan kerja mengikuti [README rencana](../README.md).

Catat bahwa pengusul baseline boleh menyetujui pengajuannya sendiri jika berwenang sebagai approver. ## Paket 01 · Fondasi web dan akses

- Bootstrap aplikasi di akar repositori dengan Laravel 13, Inertia, React/TypeScript, Tailwind, dan Vite. Jalankan PHP 8.4 dan MySQL 8.4 terpisah dari XAMPP yang saat ini menyediakan PHP 8.2 dan MariaDB. Gunakan Node.js 22 dan simpan lockfile. Tambahkan README instalasi lokal, konfigurasi lingkungan tanpa rahasia, fixture pengembangan, serta GitHub Actions untuk lint, pemeriksaan tipe, build, migrasi MySQL, dan tes. Tambahkan `AGENTS.md` yang mewajibkan pembaruan katalog izin dan tes otorisasi saat aksi berubah. [Laravel Starter Kits](https://laravel.com/framework/docs/13.x/starter-kits) · [Vite](https://vite.dev/guide/)
- Gunakan satu akun lokal per email dan satu keanggotaan per akun di setiap organisasi, dengan tipe pengguna yang dapat berbeda. Administrator pusat mengelola seluruh organisasi. Administrator organisasi mengelola anggota, izin, dan proyek di organisasinya. Untuk pengguna biasa, kebijakan server memeriksa keanggotaan organisasi aktif, izin aksi, dan cakupan proyek. Sediakan pemilih organisasi dan proyek, daftar anggota, serta halaman matriks izin per organisasi. Berikan izin awal sesuai matriks paket 01 dan gunakan izin eksplisit untuk nilai kontrak, dokumen, persetujuan, dan pembukaan kembali data resmi.
- Sediakan login lokal, pembatasan percobaan login, reset sandi lewat email, pengelolaan akun dan keanggotaan, serta perintah interaktif untuk membuat Administrator pusat pertama. Pencabutan akun memutus sesi dan semua token perangkat. Pencabutan keanggotaan memutus akses serta token untuk organisasi tersebut. Administrator organisasi mengundang anggota melalui email dan mengelola keanggotaannya dalam cakupan organisasi.
- Buat master proyek kapal dengan nomor unik per organisasi, metadata kapal, pemilik, galangan, tanggal, nilai kontrak dan mata uang, Project Manager, anggota, PIC, serta approver baseline yang ditunjuk. Sediakan penutupan dan arsip dengan histori yang tetap dapat dibaca sesuai izin. Simpan dokumen pada disk lokal privat dengan validasi unggahan, pemeriksaan izin setiap kali diunduh, dan pembersihan berkas jika penyimpanan gagal. Catat perubahan akun, izin, proyek, dokumen, dan baseline dalam audit beserta aktor, waktu, objek, perubahan penting, dan alasan bila diperlukan.
- Sediakan `POST /api/v1/auth/tokens`, `DELETE /api/v1/auth/tokens/current`, `GET /api/v1/me`, serta daftar dan detail `/api/v1/projects`. Token Sanctum terikat pada akun, perangkat, dan satu organisasi, berlaku 30 hari, serta dapat dicabut dari web. Penerbitan ulang untuk perangkat yang sama di organisasi yang sama mengganti token sebelumnya. API dan web memakai kebijakan akses proyek yang sama. [Laravel Sanctum](https://laravel.com/framework/docs/sanctum)

## Paket 02 · WBS dan baseline

- Buat editor kategori, subkategori, dan item dengan ID stabil, kode unik per proyek, satuan, volume, urutan, tanggal, PIC, serta referensi sumber. Hanya item daun yang diukur. Simpan bobot lokal terhadap induk dengan desimal presisi tetap dan turunkan bobot proyek dari hierarki. Validasi siklus, induk lintas proyek, bobot positif, dan total 100% untuk tiap kelompok saat pengajuan.
- Sediakan template struktur proyek Ferry dan Tug serta template pengukuran Material, Konstruksi, Pengecatan, dan Drawing. Dukung persentase langsung dan tahapan berbobot dengan bobot efektif untuk subtahap. Saat template disalin, simpan tipe reviewer pada WBS tujuan dan validasi daftar pembaca terhadap anggota aktif proyek. Daftar pembaca membatasi pengguna biasa jika diaktifkan dan tetap berlaku ketika anggota dicabut.
- Sediakan kalender bulanan dan editor target kumulatif. Validasi rentang 0–100%, urutan periode, jadwal item, dan target 100% pada bulan penyelesaian untuk baseline per item. Tampilkan target yang belum tersedia sebagai kosong. Untuk baseline legacy, simpan angka agregat pada level kategori atau proyek beserta satuan dan sumbernya. Angka kategori yang sudah berupa kontribusi proyek dijumlahkan sekali.
- Terapkan alur draf, perbandingan dengan versi yang berlaku, pengajuan, pengembalian dengan alasan, dan persetujuan. Publikasi menyimpan versi bobot, struktur, target, alasan, dan bulan efektif secara atomik. Periode yang sudah memiliki hasil resmi tetap merujuk versi baseline yang digunakan saat publikasi hasil tersebut. Untuk periode lain, gunakan versi terbit dengan bulan efektif terbaru yang mencakup periode itu, lalu nomor revisi terbaru jika bulan efektif sama. Pertahankan ID saat item dipindah dan catat relasi asal saat item dipecah atau digabung untuk dipakai paket 03.
- Tambahkan `GET /api/v1/projects/{projectId}/wbs` dan `GET /api/v1/wbs-items/{itemId}`. Parameter `period` memakai `YYYY-MM` dan default bulan berjalan di `Asia/Jakarta`. Endpoint menyajikan WBS dari baseline terbit yang berlaku untuk periode tersebut. Dokumentasikan ID string, nilai desimal, pagination, status tanpa baseline, dan respons error dalam OpenAPI 3.1. Turunkan koleksi Postman lokal dari spesifikasi dan sertakan environment contoh tanpa kredensial. [Postman CLI untuk OpenAPI](https://learning.postman.com/latest-v-12/docs/postman-cli/postman-cli-governance)

## Pengujian dan penerimaan

- **Akses dan dokumen.** Uji dua organisasi dengan nomor proyek yang sama, satu akun dengan peran berbeda di tiap organisasi, kedua tipe Administrator, dan pembatasan WBS. Periksa daftar, URL langsung, unduhan, audit, reset sandi, serta dampak pencabutan akun, keanggotaan, dan token.
- **WBS dan baseline.** Uji bobot bertingkat, dua metode pengukuran, target kosong dan nol, tanggal dan total yang tidak valid, serta histori revisi. Verifikasi Material 80/10/10 dengan capaian 80/50/20 menghasilkan progres fisik **71%**, dan fixture Ferry menghasilkan rencana Oktober **30,693%**. Uji persetujuan oleh pengusul yang berwenang, persetujuan bersamaan atau diulang, dan pemilihan versi untuk periode yang sudah resmi.
- **Web dan API.** Jalankan lint, build, tes Laravel dengan MySQL 8.4, serta koleksi Postman terhadap aplikasi lokal. Verifikasi alur login, proyek, pengguna, WBS, dan persetujuan di desktop dan ponsel. Paket berikutnya melanjutkan progres aktual dan koreksi, impor Excel, dashboard dan ekspor, biaya, serta serah terima Android sesuai urutan di README.
